## 二 总体知识之间的关系

以“提交一笔报销”为例：数据结构决定如何组织输入和查找记录；设计模式帮助隔离变化的规则；数据库约束和事务保证数据状态；SQL负责查询和汇总；操作系统与网络影响并发和请求传递；测试检查边界与失败；安全检查谁能对哪笔报销执行操作。

同一个题干可能跨几个方向。“两次点击生成两笔报销”既涉及接口幂等，也涉及数据库唯一约束和并发测试。“已登录却能查别人的单据”首先是对象授权问题，不能只用加密或索引回答。先明确题目要解决的问题，再匹配知识点。

| 题干提示 | 优先想到的知识 | 需要再判断的条件 |
|---|---|---|
| 根据不同规则切换计算方式 | 策略模式 | 流程是否固定，变化是否在算法 |
| 不同厂商的一整套相关对象 | 抽象工厂 | 是一个产品还是一组配套产品 |
| 两次读取结果变化 | 隔离与并发异常 | 是否读了未提交值，是同一行变化还是结果集变化 |
| 没有记录的人也显示0 | LEFT JOIN与聚合 | 条件放ON还是WHERE，COUNT数哪一列 |
| 查询变慢 | 索引与执行计划 | 数据规模、选择性、扫描范围、排序与回表 |
| 等待互相占用的资源 | 死锁 | 资源实例数、等待关系是否成环 |
| 重试导致重复业务结果 | 幂等与事务 | 请求键、唯一约束、内容一致性、外部副作用 |
| 请求能操作他人数据 | 认证与授权 | 服务端是否验证对象归属与操作权限 |

## 三 阅读和做题的方法

每次用40至60分钟完成一个小节：先读知识解释10至15分钟，再遮住答案独立做3至5题，最后写出理由并复盘。不必一天读完所有文件。

答案写成“结论＋题干条件＋原理＋其他选项的问题”。选择题即使猜对，也要标记不确定；SQL先手算结果，再运行；计算题保留推导。把“选错概念、漏条件、计算失误、不会实现、题意有歧义”分开记录，复习动作才具体。

原有 [11 笔试题学习档案](https://github.com/Vi01etttt/Learning/blob/main/autumn-recruitment/11_%E7%AC%94%E8%AF%95%E9%A2%98%E5%AD%A6%E4%B9%A0%E6%A1%A3%E6%A1%88.md) 保留大模型微调题、真实个人作答和历史错题。本目录负责系统专题与原创训练；以后收到真实题目仍追加到原档案，并在新错题记录里链接相关专题，不重复计算题量。

## 四 七次学习安排

下面是按学习次数安排的建议，不是已创建的日历提醒，也不要求连续七天完成。每次基础学习60至90分钟，SQL实操可额外安排30分钟。

| 次数 | 重点 | 当次产出 |
|---|---|---|
| 1 | 设计模式三类与策略、工厂、适配器、代理、装饰器 | 用自己的话比较5组概念；做6题 |
| 2 | 其余重点模式、SOLID与场景辨别 | 做剩余6题；不看资料解释一个代码例子 |
| 3 | 关系模型、键、范式和SQL基础 | 画拆表前后关系；完成SQL01至SQL05 |
| 4 | ACID、隔离、MVCC、锁、索引 | 画两条事务时间线；完成基础DB-01至DB-12 |
| 5 | SQL进阶与数据结构算法 | 完成SQL06至SQL10，核对输出；做算法5题 |
| 6 | 操作系统、网络、测试与安全 | 做剩余基础10题和软件工程10题；写8条业务用例 |
| 7 | 综合自测与错题重做 | 40分钟闭卷做20题；把错因写入记录 |

时间不足时，先学设计模式核心比较、事务与隔离、索引基础、SQL的NULL与JOIN，再做自测暴露短板。不要把“背了术语”当成“能做题”。

## 六 学习完成标准

- [ ] 能解释设计模式的变化点，并区分工厂与策略、适配器与装饰器、代理与外观。

- [ ] 能计算Cache地址字段、CPU时间与流水线周期，区分编译阶段并求简单文法集合。
- [ ] 能区分标准隔离级别和MySQL InnoDB中的快照读、加锁读。
- [ ] 能独立写分组、外连接、NOT EXISTS与排名查询，解释NULL和重复统计。
- [ ] 能完成复杂度、基础进程线程、死锁、TCP与子网题。
- [ ] 能为接口设计正常、异常、权限、重复和并发用例。
- [ ] 完成一次闭卷综合自测，并保留本人答案、理由和复测结果。

这些勾选项等待本人学习验证，不因笔记已建立而标为完成。后续按实际错题新增专题或扩充例题，保持题号和对应知识稳定。
