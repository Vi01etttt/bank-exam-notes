## 二 答案与讲解

### MIX01至MIX04 设计模式

**MIX01：B。** 变化是可替换的计算算法，策略直接封装这个变化。A控制实例数量；C转换接口；D通知订阅者。本题不是对象创建问题。复习 [设计模式](01_设计模式.md) 中的策略与工厂比较。

**MIX02：A。** 多个相关产品组成同一平台的产品族，抽象工厂提供配套创建接口。B负责依次处理请求，C控制实例，D依据内部状态切换行为。本题要区分“一个产品的创建”与“一组配套产品”。复习设计模式的抽象工厂。

**MIX03：C。** 新旧接口不兼容，适配器做转换与委托；并不要求复制对象、固定算法步骤或广播事件，因此A、B、D不匹配。复习设计模式的适配器。

**MIX04：A、C。** 创建数量、状态并发保护、跨进程共享是不同问题。B把进程内对象错误推广到跨进程，D引入全局状态和生命周期问题而没有需求依据。复习设计模式的单例边界。

### MIX05至MIX08 数据库

**MIX05：B。** 扣款与入账共同成功或撤销，体现原子性。A强调已提交结果在规定故障模型与持久化配置下保留；C、D不是ACID属性。实际转账还需要约束和业务逻辑来保证一致性。复习 [数据库原理](02_数据库原理.md) 的ACID。

**MIX06：A、C。** A描述左前缀的常用查找方式，C说明维护索引要付成本。B忽略小表、低选择性和回表等情况；D忽略索引扫描、覆盖及特定优化路径，不能说绝不使用。是否选用要看执行计划。复习数据库原理的联合索引。

**MIX07：不可重复读。** 同一行在两次读取间被另一个事务提交修改。不是脏读，因为T2已提交；题干没有新增或减少匹配行，不是典型幻读描述。只根据结果判断异常，不从题干反推具体引擎和隔离配置。复习数据库原理的并发异常时间线。

**MIX08：不满足2NF。** 姓名只依赖复合候选键的一部分学号，课程名只依赖课程号，存在非主属性对候选键的部分依赖。拆为 `学生(学号,姓名)`、`课程(课程号,课程名)`、`选课(学号,课程号,成绩)`，选课的两列分别引用学生和课程。按给定依赖，拆后的关系消除了上述部分依赖；是否有其他问题还看真实依赖。复习数据库原理的范式推导。

### MIX09至MIX12 SQL

**MIX09：B。** 外连接保留一条补位行，COUNT(*)数成1；COUNT右表主键忽略NULL，结果0。A漏掉补位行，C把NULL数进去，D两项都错。复习 [SQL04](03_SQL题目与实操.md)。

**MIX10：C。** WHERE先过滤已批准明细，GROUP BY汇总，HAVING筛汇总结果。A放反处理阶段，B误用排序，D会漏掉多笔较小金额组成的大总额。复习SQL03。

**MIX11：B。** DENSE_RANK并列同名且连续，故1、1、2。A是ROW_NUMBER的序号形式，C是RANK，D不是这些函数的起始排名。复习SQL07。

**MIX12：A。** id1因匹配1不入选；id2、3与NULL比较形成UNKNOWN，WHERE也不保留。不是简单“排除1后剩两行”。复习SQL06。

### MIX13至MIX16 计算机基础

**MIX13：Θ(log n)，常写O(log n)。** 第k次迭代开始前i为 `2^(k-1)`，执行次数为 `floor(log2(n))+1`。每次只做常数操作，因此总成本随对数增长；n=1时执行一次。复习 [计算机基础](04_计算机基础.md) 的复杂度，不要看到while就判成O(n)。

**MIX14：B。** 同进程线程通常共享地址空间等资源，各有自己的调用栈、寄存器状态与执行位置；A、C混淆线程私有执行状态，D描述进程隔离。复习计算机基础的进程线程。

**MIX15：A。** 不能一边持有部分资源一边等其他资源，破坏占有并等待。互斥仍可存在；C、D不是四个死锁必要条件。代价可能是资源利用率下降，不能只看“能防死锁”而忽略性能。复习计算机基础的死锁。

**MIX16：C。** HTTP幂等说的是多次相同请求的预期效果；返回结果可能随当前状态变化，日志也可重复。POST本身没有标准幂等保证，但业务可加请求键实现具体操作幂等。复习计算机基础的HTTP；标准语义见 [RFC 9110幂等方法](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)。

### MIX17至MIX20 测试与安全

**MIX17：B。** 两个二值条件各有真假，组合数 `2²=4`。四组分别为真真、真假、假真、假假。复习 [测试与安全SE03](05_软件工程测试与安全.md)。

**MIX18：B。** 仅本地在受控响应下的行为被验证。A、C需真实连接证据，D忽略集成风险。复习SE06。

**MIX19：B。** 参数化防SQL结构被用户值改变，授权防用户操作无权限对象。两者保护不同边界。A重新引入注入风险，C只影响访问成本，D掩盖错误。复习SE08和SE09；授权原则见 [OWASP授权说明](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。

**MIX20：参考答案如下，具体错误码按接口契约确定。**

| 场景 | 预期响应与数据状态 |
|---|---|
| 自己的草稿、金额1分 | 成功，草稿进入已提交，只产生一份提交结果 |
| 自己的草稿、金额100000分 | 成功，边界被接受 |
| 金额0或100001分 | 校验拒绝，状态和提交记录不变 |
| 金额小数或缺失 | 类型或必填校验拒绝，数据不变 |
| 提交他人的草稿 | 拒绝授权，双方数据均不变 |
| 提交已批准记录 | 拒绝状态转换，金额和状态不变 |
| 同键同内容重复请求 | 复用原结果，不重复创建或累计金额 |
| 同键不同内容 | 返回冲突，不覆盖原操作内容 |
| 两个同键同内容请求同时到达 | 最终仅一份结果，另一个按契约复用结果或受控等待后返回 |
| 在事务提交前制造写入失败 | 返回失败，所有本事务变更回滚，原草稿保留 |

这10行是参考集合，前面的复合异常应拆成具体输入执行。每条都要检查响应和持久化数据，不能只检查HTTP状态码。并发用例需要真的让请求重叠；失败用例要确认失败发生在提交前。如果涉及外部支付或邮件，还应增加副作用一致性测试。复习SE02、SE04、SE07与数据库事务。

## 三 如何记录自测结果

16道选择题各1分，多选题须完整正确；MIX07、08、13、20各2分，总分24分。MIX07、08、13各按“结论1分、推导理由1分”自评。MIX20单独评分：场景覆盖1分，要求至少8个可执行场景且包含权限、状态、重复、并发和回滚；预期结果1分，要求响应与持久化状态均准确。此评分仅便于个人复测，不对应企业合格线。

优先记录错因与耗时，而非只看总分。把做错或猜对的题带回对应专题，隔一天不看答案重做，再隔三天做一次变式。没有本人作答前，本页不填写正确率或完成状态。
